# Sensa 浏览器扩展

扩展负责网页和字幕阅读、选区采集、解释以及向生产 Web 交接。用户行为见 [`docs/sensa/product-requirements-v1.md`](../../docs/sensa/product-requirements-v1.md)，工程边界见 [`docs/sensa/engineering.md`](../../docs/sensa/engineering.md)。

构建：

```sh
npm run build -w @sensa/browser-extension
```

生产扩展在 Chrome 开发者模式加载 `apps/browser-extension/dist`。重新构建后需要重新加载扩展，并刷新已经打开的 Sensa 页面。本机预览由 `npm run dev:sensa` 或 `npm run preview:sensa` 单独生成并加载 `apps/browser-extension/dist-local`，不会覆盖生产扩展。

正式构建必须同时设置 `SENSA_EXTENSION_WEB_URL` 和 `SENSA_EXTENSION_API_URL`；非 loopback 地址必须使用 HTTPS。没有设置目标的仓库构建只把编译检查产物写入 `.tmp/browser-extension-build`，绝不改写可能已被 Chrome 加载的 `dist`。模型密钥不得进入扩展 bundle 或 storage，`dist/` 不提交 Git。

无付费交互检查：

```sh
node --import tsx scripts/sensaBrowserPortSmoke.mts
node --import tsx scripts/sensaExtensionPopupSmoke.mts
```

页面桥只有一份声明：`packages/contracts/src/sensa/consumer/extension.ts` 同时写明握手（授权、交换、凭据）与页面桥（每种请求的 kind 与载荷、每种应答的形状）。Web 应用按它构造请求并读取应答，`background.ts` 在分发前解析每条桥消息——未声明的字段被拒绝而不是被丢弃；页面侧的 `webBridge.ts` 每个 Sensa 页面都会加载，所以不带 schema，它的频道名、id 上限与 kind 白名单在构建时从同一份声明注入，页面因此无法借桥的频道触达扩展的其他功能。`scripts/sensaBridgeContractSmoke.mts`（在 `npm run check` 里）把真实 forwarder 与真实 background 装进同一台假浏览器逐 kind 验证。

阅读面的语言规则：正在读的文字是什么语言，由文字自己决定（本地检测优先，页面声明与字幕轨代码兜底，检测只在本版本语言目录内选择）；学习者需要哪种语言，由 Web 应用发布的语对决定，扩展不持有也不编辑它。学习者已经能读的文字不会被自动翻译——页面按段判断（一篇文章可以引用第二门语言），字幕按轨判断（一条字幕轨只有一种语言）——而显式请求（划词、`Alt + T`、「翻译本句」）从不跳过。

翻译发出去时带着文字所处的上下文（页面标题、所在小标题、相邻段落；字幕则带视频标题与前后两句），它是判断意思的依据，本身不会被翻译。

每条阅读请求都由 background 补齐学习者自己的状态：语对（由 Web 应用发布）与术语表（学习者在 Web 端写下、随库同步）。补齐只发生在一个地方，流式端口与普通消息两条路径共用它——分开写的那一份曾经漏掉语对，于是每个段落都被服务端拒绝。模型连接测试与模型列表不是阅读请求，它们只带自己的那个问题。

术语表和语对一样由本机库拥有：扩展只保存发布来的副本，不提供编辑入口，第二份可编辑的副本正是两个界面开始不一致的方式。术语表只影响用词，不改变意思，也不承诺模型每次都照做。

朗读本页（页面阅读面板里的按钮）按文档顺序朗读页面的文字块，每块用它自己的语言：语言按块检测（一页可以引用第二门语言），检测不出来时才用页面声明，两者都没有就不朗读。容器块（`div`）不参与，否则容器和里面的段落会被读两遍；可编辑区域不朗读，理由与不翻译它相同；正在朗读的块会高亮并滚动到视野中，停止时一并清除。设备没有该语言的声音、页面没有可朗读文字、语言无法确定，三种情况分别给出不同提示，不留一个按了没反应的按钮。

输入框翻译是唯一反向的阅读请求：其他功能把学习者读到的内容变成他熟悉的语言，这个把他自己写下的句子变成他正在学的语言（服务端按语对判断方向）。只有学习者真的会写句子的输入框会被读取——`text`/`search`、`textarea`、`contenteditable`，密码框永不读取，只读或禁用的框不读；快捷键与翻译段落相同（`Alt + T`，焦点在输入框里时翻译你写的内容），上下文取输入框所处的页面（标题、上级小标题、相邻文字），因为那是他在回复的东西。翻译不会被自动写入：面板先给出译文，学习者点「替换输入框内容」才写入，写入走插入（`execCommand('insertText')`，失败时回退到原生 setter），因此受控组件不会把内容丢掉、浏览器仍可撤销；按 Esc 关闭面板，输入框保持原样。这里是显式请求，所以从不跳过。

站点规则（「本站不再开启阅读」）由 background 从**当前标签页自己的域名**写入，消息里带来的站点名一律不采信；写入同时会关掉该标签页的阅读，所以面板消失是因为这里已经关了阅读，而不是按钮把自己藏起来。规则生效后：该站点不再被注入内容脚本、工具栏按钮会拒绝开启并给出原因，恢复入口在插件弹窗（显示当前规则并一键解除）。偏好只有 `preferences.ts` 的 `saveReadingPreferences` 一个写入者，设置页与页面内开关都经过它，所以两端读到的规则是同一个。

朗读只用浏览器本机语音，按文字自己的语言选声（语速、locale 与优先音色规则与 Web 端的设备语音一致），只使用本机已安装的声库，语言无法确定的文字不朗读。学习者可以在设置页从本机音色里指定一个：指定音色在该语言下优先于启发式选择（按语言匹配，因此英式英语音色可以用于英语文本），换到它念不了的语言则被忽略而不是照用；音色属于设备，所以列表只来自本机，别处选过的名字在这台机器上不成立。

这些检查使用本地或受控替身，不证明真实第三方站点、浏览器商店安装或真实模型质量。
