# Sensa 前端体验与视觉方向探索

> 状态：Experimental design exploration
> 当前工作主题：Living Semantic Field｜生长的语义场
> 更新日期：2026-08-30
> 权威级别：非规范性、可修改、可替换、可废弃

## 1. 文档地位

本文记录一次用于推动前端原型的设计尝试，不是不可更改的设计规范，也不属于 Sensa 领域模型、
V1 PRD、品牌标准、实现合同或法律结论。本文中的主题、原则、视觉假设、交互语言和首页构想都
需要经过原型、可用性、可访问性和产品辨识度验证；任何一项都可以在获得新证据后被修改、拆分、
替换或废弃，不需要为了维护本文而扭曲领域模型。

发生冲突时，统一语言和产品边界由 `CONTEXT.md` 决定，运行行为由领域模型决定，产品 IA 与
验收由 `product-requirements-v1.md` 决定。本文只能探索这些事实应当怎样被表达，不能改变它们。

本文也不证明产品已经消除知识产权或其他法律风险。相关判断需要独立的设计来源记录、素材与
代码审计，以及必要时的专业法律意见。

## 2. 探索目标

Sensa 可以保留成熟语言学习产品中已经证明有用的体验价值，例如全屏专注、低操作成本、连续
学习节奏、即时反馈和按需深入内容；但不继续复用不背单词具有辨识度的页面布局、卡片结构、
工具栏、视觉层级、颜色、图标、插画、文案语气、动效、手势、素材或整体 look-and-feel。

即使产品 IA 相近，其表达也必须从 Sensa 的 Sense-first 领域模型独立推导和记录，而不是对已有
产品界面进行换色、重排或逐屏复刻。

| 可继承的体验目标 | 需要独立设计的 Sensa 表达 |
| --- | --- |
| 全屏专注，一次完成一个主要任务 | 页面构图、学习画布和上下文工具 |
| 操作负担低，学习节奏连续 | 控件层级、反馈方式、转场和手势 |
| 作答后立即获得有用解释 | Outcome、repair 与例句资源的呈现 |
| 词典、例句、笔记可以按需深入 | 辅助内容入口和信息组织 |
| 今日状态和完成感清晰 | Mixed Learn 与 Review-only 的首页表达 |

## 3. 当前工作假设：Living Semantic Field

当前尝试把 Sensa 理解为一个“生长的语义场”：产品不是呈现一叠等待翻面的单词卡，而是帮助
一个具体 Sense 的意思连接被建立、区分、提取、迁移、长期保持，并在遗忘后得到定向修复。

“语义场”首先是一种体验与视觉隐喻，不等于把领域中的 Semantic Field 对象直接画成节点图，
也不要求所有页面出现连线、网络或地图。若该隐喻造成认知负担或流于装饰，应当被收缩或替换。

## 4. 当前体验原则

### 4.1 Sense before Word

学习界面围绕“这个表达在当前语境中是什么意思”组织。Lexeme 可以承担查找和呈现身份，但不能
重新成为学习、毕业和复习的隐含身份。

### 4.2 Experience before Explanation

新 Sense 优先从可感知、可想象或可操作的 Experience 建立连接，再主动揭示形式、桥接、发音与
例句。文字场景是一条完整的经验建立路径，不是对交互或图片的说明文字。

### 4.3 One Encounter, One Intention

一次 Encounter 的页面只强调一个主要意图。词典、例句、笔记和个人场景可以按需深入，但不与
当前任务争夺主要注意力。

### 4.4 A Stream, Not a Deck

Learn 被体验为由不同 Sense 穿插形成的连续学习流，而不是按单词逐张刷完的卡组。界面需要保持
跨 Encounter 的连续感，同时明确每次任务和反馈的局部边界。

### 4.5 Show Change, Not Scores

优先表达“连接正在建立”“边界仍不稳定”“已经可以独立提取”“进入长期保持”或“需要定向
修复”，不把等级、机械次数或一个总掌握百分比包装成领域事实。

### 4.6 Evidence over Self-rating

正式 Review 通过具体行为产生 Outcome；不重新建立以“忘记、模糊、认识、简单”自评按钮为核心
的复习体验。解释和 repair 可以帮助学习，但不能伪装成独立成功 Evidence。

### 4.7 Calm, Not Gamified

产品可以有节奏、反馈和完成感，但当前方向不依赖金币、惩罚焦虑、夸张庆祝或把连续签到作为
学习真实性的替代。Sensa 尝试成为一件安静、可信且响应迅速的认知工具。

## 5. 当前视觉假设

这些内容只是方向约束，不是已经确定的 design tokens：

- 以温暖低饱和背景和高可读墨色文字形成适合长时间学习的基础画布；
- 探索矿物蓝或深青作为主要操作与稳定连接色，陶土色作为注意或 repair 信号，柔和自然色作为
  稳定状态辅助；具体色值必须经过对比度与真机验证；
- 减少大量同质悬浮圆角卡片，探索连续画布、区域、层次、焦点和迁移轨迹；
- 图形语言可以借鉴轮廓、聚焦、连接与再浮现，但不强制使用节点网络；
- 优先选择适合中英文混排的人文无衬线字体，限制字体家族与字重数量；
- 建立 Sensa 自有图标体系，不继续依赖旧原型的 sprite、组合和视觉比例；
- 颜色不能成为正确、失败、到期或 repair 的唯一信息通道，文字、形状和层级必须共同表达状态；
- 正文、主要控件和焦点状态至少以 WCAG AA 为目标，并从移动端约束开始设计。

## 6. 当前动效假设

动效用于解释状态变化，而不是制造装饰性兴奋：

- Experience 到 Reveal 表达形式进入已有意思结构；
- Sense 之间的切换表达学习流中的穿插，而不是卡片堆的机械翻页；
- Recognition、Recall 和 Transfer 成功分别表达边界清晰、连接闭合和结构迁移；
- Graduation 表达进入长期保持，而不是永久掌握；
- due Review 表达一个 Sense 在合适时间重新浮现；
- Review 失败表达局部连接需要修复，不清零既有学习，也不使用惩罚性震动或夸张错误动画。

微反馈暂以约 100–150ms、小型状态转换约 200–300ms 为探索范围；所有长动效必须可中断，页面在
关闭动效时仍可完成任务，并尊重 `prefers-reduced-motion`。

## 7. 首页的第一版设计假设

首页保留已接受的 IA，但重新设计其表达：

- 一个主要的 Mixed Learn 入口，表达“开始或继续今天的学习”；
- 主入口可以轻量说明它将统一处理 due Review、Review-originated Relearning、ready initial
  Acquisition 和额度允许的新 Sense Introduction，但不把四类 inventory 做成互相竞争的任务卡；
- 一个次要的 Review-only 入口，只处理 due Retention 和 ready Relearning；无候选时禁用或弱化；
- 新学、进行中和待复习数字是服务端事实摘要，不被表现成客户端固定队列或待清空债务；
- 首页应让用户感到今天有一条可以继续的学习流，而不是面对一组需要逐个消除的计数器。

## 8. 需要验证的问题

下一轮首页与 Learn/Review 原型至少需要回答：

1. “生长的语义场”是否帮助理解 Sensa，还是只形成抽象装饰？
2. 安静的视觉方向能否保持足够清晰的主操作和完成感？
3. Mixed Learn 与 Review-only 的主次关系是否无需解释即可理解？
4. Experience、Assessment、Feedback 和 Repair 是否能被用户自然区分？
5. 中英文混排、长文本、弱视、色觉差异和 reduced motion 下是否仍可完成主要流程？
6. 新设计是否具有独立来源和可辨识的 Sensa 表达，而不是对参考产品进行表面换皮？

在这些问题获得原型与用户证据前，本文只能作为下一次设计尝试的起点。
