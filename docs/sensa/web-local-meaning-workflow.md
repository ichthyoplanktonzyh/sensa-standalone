### 下载和本机数据

Hono `GET /sensa/packages` 检查账号准入，读取部署配置 `SENSA_PACKAGE_CATALOG_JSON`，
形状为 `{ "items": [...] }`；未配置时返回真实空目录，不返回样例。条目合同见
`packages/contracts/src/sensa/consumer/learningPackage.ts`，包括包 ID、版本、标题、简介、
目标数量、字节数、SHA-256 和下载 URL。生产 URL 为 HTTPS，允许 loopback HTTP 用于本地验证；
资源服务器需允许 Web 的 CORS 读取。认证令牌仅发给 Hono，资源下载不携带凭据、不跟随跳转。
目录配置及发布继续走 CI/CD；目前没有线上环境和已发布目录，本轮未执行发布。

Web 当前接受 `sensa-learning-package-v1` JSON：en → zh-CN、最多 100 个目标、8 MiB，
每个目标携带 Sense/Binding 的稳定 ID 和版本，以及共享 compact materialization 内容。
它是当前 Web 的传输合同，**不是**原生 `sensa-local-text-pack-v1` 的兼容读取器。

## 第三项：Intake 到个人内容学习（2026-09-10）

本次接通完整应用的另一条主路径：Intake 原始材料与来源 → 快/慢轨 → 必要时澄清 →
明确确认意义 → 显式加入学习 → 生成资源 → 独立审核 → 第二项本地 Runtime。

不新增裁剪应用或另一套学习运行时。快轨已接受内容不再次强迫澄清；慢轨仍须候选确认。

### 本机事实与共享材料规则

IndexedDB 升至 v3，仅追加 `personalLearning` 与 `contentAttempts`。前者保存显式学习意图、
固定意义/表达版本、计划版本及准备状态；后者保存每次请求、候选、独立审核、校验结果、
模型接收方、授权与中断状态。没有授权 Key 入库。旧包、已运行目标和原型历史均不迁移。
状态分别为 waiting / generating / reviewing / failed / rejected / stopped / ready。
加入不等于可运行，也不建立完成记录；未就绪目标可在原学习列表/详情中继续准备。

将服务端已有 makeRequest / makeBundle / validateBundle 和固定生成/审核提示词移至
`packages/contracts/src/sensa/contentExecution.ts`，服务端保留实际模型 transport 并复用
同一实现。Web 走已有默认 Sensa gateway（高级自定义服务仍可选），使用两个独立调用：
生成器只提交候选；审核器只接收固定事实与候选，不能修改目标或生成替代材料。
独立调用可以使用同一模型，但不共享生成对话。确定性 schema、摘要、角色需求、表达/
释义一致性和答案泄漏检查同样必须通过；模型返回 accepted 并不能绕过这些校验。

通过后，候选、审核证据、就绪状态与实际 LocalLearningTarget 在一个本机事务提交。
目标 ID 与学习包使用相同 Sense/Binding 版本身份算法；重复加入或已存在的目标复用原材料
和进度，不重复生成、不重置 FSRS。on-demand 材料不伪装成 published 学习包。
此后的数量确认、首次学习、复习、再学习、动作去重和离线恢复全部走第二项运行时。

### 请求、隐私与恢复

默认生成/审核仅接收已确认意思、表达和通用原型场景，不发送原始 Intake 内容。
已确认详情提供单独勾选，允许生成/审核使用原文；每次点击准备前显示两个接收方，
保存对应原文摘要、grant ID 与接收方。Intake 采集或意义接受不被当作生成原文使用授权。

一次点击最多生成一次、审核一次，不做后台自动重试；一条内容 24 小时最多 6 次准备尝试。
生成遵守固定请求的时间预算，整体执行有上限和 120 秒租约。刷新只读状态，不自动调用模型。
生成后的候选先保存；审核服务中断或最终写入失败后，在原接收方配置未改变时重试仅审核
原候选，并记录 resumedFrom。拒绝材料必须重新生成并审核。租约过期可恢复，用户也可停止。
停止、来源版本变化、Provider 配置/用途变化、退出或新尝试均阻止旧请求发布就绪材料。
更换模型后须由用户在显示新接收方的页面重新点击准备。运行中的材料不会被重试覆盖。
在线 token 获取也受取消/超时约束，避免认证恢复让生成请求无限等待。
