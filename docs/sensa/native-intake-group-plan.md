# 统一采集与本机交接大组

2026-09-09 Owner 已确认并授权整组实施：Web 与原生分别持有本地副本；浏览器插件可选 Web 或原生接收端。本地 Agent 通过 CLI 调用本机准入，无需打开 Flutter 或网站。Web 本地化、远程 Agent 中继和同步不在本组施工。

用户流程：原生库明确配置本机桥接 → 插件确认接收库 → 网页/YouTube 保存待处理或明确接受已解释的意义 → 获得库内回执 → 原生收件箱/语义世界继续处理。模型账号与保存目的地分离；原文采集离线可用，在线解释仍使用已配置阅读服务。连接失败保留目的地固定的队列，换库不转投旧队列，不把排队称为入库成功。

统一输入复用 Capture/Proposal 合同，包括来源和字幕定位；Context 必须存在，Expression/Sense 不足则进入收件箱，Focus 非必需。完整提案仍需直接确认或明确授权的 Agent 接受，不能自动加入学习。CLI 与插件只暴露有界采集、连接信息和单操作回执，不能任意执行内核命令或读取全部资料。Rust 原子写入语义事实与回执，按接收库/调用方/操作 ID 幂等；同 ID 改内容拒绝。

实现边界：共享 TS 合同，Rust intake 事务与桌面 CLI/Native Messaging host，插件独立持久队列和接收目标 UI，原生导入/刷新入口，面向 Agent 的调用说明。沿用现有 Web 交接回归。验收包括真实进程/浏览器桥接、断线重试/重复/换库、来源定位、快慢轨、原生展示/冷恢复；合成资料与本机 fixture，无付费调用、不访问 owner 库。
