# Sensa 开发工作约定

这是当前可调整的协作约定，不属于领域模型或发布完成证明。适用于正式 Web、插件、API、
共享模块和原生客户端；AGENTS.md 与 owner 本次明确指令优先。

## 职责与依据

Owner 决定产品取舍、用户流程、范围和验收。主代理直接承担需求梳理、架构、实现、审查、
验证与交付；当前不使用 worker/subagent/OpenCode，不创建新工作树。模块间的职责、数据
所有权和依赖先明确，再完成每条用户用例；后端旧形状不反过来决定产品体验。

七份领域模型裁决身份、不变量与所有权；PRD 裁决界面和旅程；current-stage 维护当前状态，
production-migration-plan 维护依赖与发布门。旧 Consumer 只按兼容参考维护。原 Web 成果必须
复用，不新增简化替代页、重复编排或方法专用硬编码链；原型行为不能冒充正式事实。

## 用例工作循环

1. 明确用户从哪里开始、完成什么，以及前置、成功/失败/恢复状态。
2. 与 owner 确认前端体验，包括布局、主要动作、结果与退出；相同范围已有确认直接复用，
   不重复申请。技术探查可先行，不能当作未经确认的产品选择。
3. 细化模块/数据所有权、消费契约、版本与持久化规则，再实现端到端纵切。模型候选、语义接受、
   学习意愿、准备、运行与调度各守边界，不以临时字段混为一个状态。
4. 验证用户可见结果与持久化事实，覆盖相关失败、重试、离开、刷新、并发与恢复；不伪造成功。
5. 完成并验证后创建本地 checkpoint，说明变化、检查与限制。提交不包含推送或部署授权。

每项任务需明确仓库/模块、相关合同、前置、责任边界、验收与不包含项。实现发现体验/领域
冲突时带回具体差异，不暗中降低要求。普通内部实现选择可自行处理，涉及产品决策及时联系 owner。

## 验证与交付

- 根级 typecheck/build/lint 加受影响的 targeted smoke；Python 修改至少编译并运行无成本 validator。
- 测试策略按真实组件、替身、数据库、独立进程恢复、OS/平台、真实 Provider 与 owner 体验分别说明。
  不因使用 Playwright/integration_test 或构建通过就声称完整产品验收。
- 程序自动化承担日常回归，整组完成集中走查；无需重复已经通过且不受修改影响的全量用例。
- 常规不调用付费 LLM/TTS。已授权的有界 DeepSeek/edge-tts 试验独立 opt-in，保留预算与证据，
  不能把一次小样本授权视为无限试验。
- 本地浏览器测试使用隔离身份与数据，保留 owner 进程/库。连接器无法处理外部平台步骤时联系 owner，
  不擅自转用浏览器接管外部账号。云端操作只走 CI/CD，不从本地 shell 部署。
- 失败保留诊断，不隐藏状态、跳过检查或用重复运行碰绿；具体证据入口见 [测试策略](testing-strategy.md)。

## 文档维护

长期文档按职责维护当前规则、操作入口和仍未解决的边界，不逐次追加“第几轮/下一纵切/本轮通过”日志。
临时命令输出、机器路径和开发过程由 Git 与测试报告追溯。阶段文件完成后将有效内容并入长期文档，
删除过时要求和重复文件，修复索引/相对链接/测试目录；不另建归档目录复制旧报告。

范围变化更新 PRD/current-stage/相关合同；实现通过、设计确认、真实平台与公开发布分别记录。
合并文档不升级历史证据，不修改发布门或 owner 数据。只有领域术语/架构决定发生变化才修改
相应领域或 ADR，不能让实现合同覆盖领域模型。工作方式按实际反馈调整，不冻结每个辅助函数。
