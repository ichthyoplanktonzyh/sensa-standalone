> 2026-09-08；本地 Chrome for Testing 149。后续发布/兼容矩阵尚未全部完成。

阅读模式和每个浮层绑定开启时的账号；保存/接受必须与当前账号及该标签页模式一致。切换或
断开账号会清空阅读模式并关闭旧浮层，迟到解释不会覆盖新账号的界面。每个账号的原队列、
installation、replica 和 epoch 独立保留；重新连接原账号恢复原操作，不重新分配到另一个账号。

原始数据，提示更新，不能静默解释未知 payload。重复 operationId 的不同载荷明确拒绝；服务端
响应通过 schema 校验后才移出队列。恢复列表区分已移除记录。

## 本地验证

- 实际扩展自动化复跑 A/B/C 整条链，额外验证未知版本保持原队列、未标版本兼容、离线队列
  在替换解包扩展版本（0.1.0 → 0.1.1）并重启浏览器后恢复。
- A 账号离线保存后断开，旧浮层关闭；登录 B 后 A 队列仍归 A，B 队列为空；模拟旧 A 浮层
  在 B 阅读模式下提交被拒绝。A 原 Web session 退出后，重新授权 A 原 installation 并同步成功。
- 根级 typecheck、production build、lint 通过；没有模型/TTS 调用，未 push/deploy。

## 原生 activeTab 验证

使用 `scripts/sensaExtensionNativeFixture.mts` 创建独立可见 Chrome profile，未修改 manifest
的 host_permissions。通过原生扩展菜单实际点击，未使用自动化 fixture 的额外站点授权：

| 场景 | 观察 |
| --- | --- |
| 未点击扩展入口 | 无权注入；Chrome 返回未请求该 host 权限 |
| 点击菜单中的 Sensa | 允许注入；登录并开启模式后，原生鼠标划词显示解释/确认浮层 |
| 同源 `/next` 导航 | 保留权限；不再次点击扩展即可划词 |
| 跨到 `localhost` 来源 | 权限失效，不显示浮层；菜单重新显示请求访问权限 |
| 再次点击 Sensa 入口 | 获得新来源权限；保留的模式意图继续生效，可以重新划词 |

原生 UI 结果由 accessibility tree/截图与无内容读取的 permission-probe 检查共同确认。
测试浏览器与 fixture 服务在验证后关闭，没有改动日常 Chrome profile。
