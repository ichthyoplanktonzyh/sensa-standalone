# 本地学习库架构与数据迁移

> 2026-09-11 首发修订：以 [ADR 0001](../adr/0001-local-library-optional-encrypted-sync.md) 的“本地优先＋普通账号云同步”为准。当前只交付 Web；原生及三端验证不阻塞首发，E2EE、恢复码和设备批准不再是首发要求。下文相关旧设计或实现记录不作为新发布合同。

本文维护本地库的应用、领域、存储、在线服务与迁移边界，不维护逐阶段施工顺序。
目标架构依据 ADR 0001–0003；各端已实现与待验收状态见 [当前阶段](current-stage.md)。
Flutter/Rust/SQLite 与 React Web/IndexedDB 是当前不同宿主实现，不能相互冒充验证。
Rust WASM 接入 Web 为独立验证任务，不能以共用 JSON 类型宣称运行内核已统一。

依赖方向：UI/采集端 → Library Application（校验/幂等/事务）→ Domain Kernel + Library Store。
资源下载与模型请求返回候选，由本地校验后通过显式命令提交；在线账号服务不拥有学习事实。
`AccountReplica/outbox` 不等于本地库，旧路径的 server grant/pending_result 不套用到本地已提交结果。
Web 账号访问体验和离线解锁遵循 PRD，不将领域库无需在线账号误解为产品必须提供匿名入口。

## 库身份与事务所有权

- `libraryId` 是个人学习库身份，创建不要求 Account；`learnerId` 在库内稳定。
  `deviceId` 与一次安装/设备授权关联，账号绑定是可选服务关系。首次本地使用不伪造云端身份。
- 数据库按库隔离；本地学习库与旧 AccountReplica 使用不同命名空间，禁止同时对同一学习历史双写。
- 命令具有 `operationId`、库身份、已知版本和明确用户意图。应用模块负责校验；UI 不提交 Completion、
  Evidence、FSRS State 或“已掌握”派生值。
- 同一操作 id + 同一规范化输入返回原结果；同 id + 不同输入拒绝。陈旧步骤/版本返回冲突，不覆盖。
- 一个存储事务包含操作账本、Attempt、Transition、Completion、Handoff/Outcome、Memory revision 和
  可同步事实。事务成功才呈现“已保存到本机”；同步成功与否不改变该结果。
- IndexedDB 的 read-modify-write 在一个事务内完成，以事务串行化处理多标签页。网络、模型、文件读取
  和异步 digest 不放进活动事务；先准备输入，再在事务中重查版本。SQLite 同样需要原子事务和唯一约束。
- 累积事实按独立对象/索引保存，不继续把整库历史塞进单个 AccountReplica JSON。批量下载先暂存校验，
  以版本清单原子发布；失败不生成半个 ready Target。
- 本机时间不再依赖服务器 grant；保存时间来源和原始时间。时钟倒退不得回写旧的 FSRS 时间，向前大跳
  的状态/校准体验在本地用例中细化。不能把服务器重放时间作为离线学习发生时间。

## 应用命令职责

以下描述应用命令职责，不是某个客户端已经发布的 wire schema：

| 意图 | 前置与结果 | 失败/恢复 |
| --- | --- | --- |
| 创建/打开库 | 无账号创建身份或恢复同一个库；每日新学数量仍需明确确认 | 不支持的版本、存储不可用不得回落为临时成功 |
| 导入固定资源 | 校验 schema、版本、digest、Target/Binding/角色覆盖与可信发布来源；原子保留内容 | 损坏、不支持的协议、必要内容缺失显示原因；导入不自动产生学习事实 |
| 加入学习 | 固定目标、入口 provenance、策略/plan；同连接去重 | 已加入返回既有目标；材料未就绪不能开始 |
| 开始/继续 | 本地选择已有 ready 目标，冻结 Policy/Run/Materialization；遵守数量和模式 | 暂无到期、今日额度、等待重学分别呈现；不要求联网 grant |
| 回答/暂停/结束 | 校验固定 Step 与版本，本机事务提交，再更新界面 | 保存失败保留当前题与可重试意图；重复提交不二次结算 |
| 重启继续 | 恢复库、同 Run、固定材料、下一次复习时间 | 必要材料缺失阻止本 Run；可选音频缺失允许文本回退 |

已确认的 Recall/Reveal、again/hard/good、数量与学习结果界面继续复用。
“本机已保存”和“同步未开启/待同步/失败”是独立状态；本地结算不再显示“等待服务器确认结果”。
浏览器宿主验收还必须包含：应用外壳和必要资源缓存、关闭进程后断网冷启动、持久存储申请/状态、
配额失败，以及独立导出/恢复。仅在已打开页面设 offline 不能证明断网重启可用；浏览器缓存也不是备份。

## 浏览器采集交接

插件继续负责这个采集端口，保存所需内容仍是 Context、Sense、Expression；Focus 是可选桥梁。
接收方是明确选定的本地库。传递固定 Capture/Proposal 与原 operationId，接收端校验并本地提交，
返回持久化回执后插件才标记交接完成；超时保持结果未知并用原 id 重试。

接收方未运行时，插件保留采集队列并明确“尚未交接”，不得把内容暂存在 Sensa 明文服务端来绕过限制。
Owner 已确认新增可选的加密云端采集交付：插件可上传加密采集信封，主应用随后接收、校验并幂等入库。
云端收到密文与本地库正式提交分别回执；这不是完整个人库同步，也不转移学习事实权威。
启用时提供独立恢复码；新设备通过恢复码或已授权设备批准加入。账号密码重置不恢复解密密钥。
未开启交付继续本机交接，不把旧采集队列自动迁移到其他库。交付信封/恢复码/设备批准已实现为独立采集传输模块；完整库同步、密钥轮换与长期设备撤销仍须另验。
Web 使用限定 origin 的消息交接，桌面使用已验收的原生桥接路径。各适配器必须验证发送来源、
库授权、窗口生命周期、重复/跨库消息及账号解绑后队列归属，不能将一种适配器的通过记录外推到其他平台。
收到 Proposal 不是 Acceptance；没有 Sense 的原文可进入待处理收件箱，不显示为完整 Personal Meaning。
原生与 Web 交接已有各自实现，范围见原生能力与 Web 工作流；旧 API 队列不自动改归属。

## 同步、备份与在线服务

同步以已提交的个人事实和附件为输入，账号认证在同步适配器；本地应用不调用 Sync 才能结算。
同库多设备不是复制整个数据库：首次 Handoff 去重、同一 due identity 的并发 Review、重复源的 Target
身份、笔记冲突和删除恢复都需要明确合并规则。保留每次原始作答；不能把两份同次 due 评价都调度，
也不能凭最后写入覆盖另一份学习历史。

在多设备施工前，以共同基线/因果依赖与稳定事件身份定义可重放顺序、有效调度选择和冲突呈现。
2026-09-09 已确认事实/版本/投影模型与分层验证，见 [事实模型蓝图](personal-library-fact-model.md)；有界 G0 冲突分类实验通过，完整学习分支裁决仍未选定，单设备完成不等于调度收敛。同步协议、算法版本、缺失依赖和未知版本恢复
必须通过乱序、重复、断点和多设备离线向量后才能启用。

首发使用普通账号认证与用户隔离，服务端允许读取同步内容。新浏览器通过账号恢复已同步资料，
不要求恢复码或原设备批准。现有加密备份仍是独立导出能力，不作为登录恢复前置。

公共资源目录只发布可下载的版本化资源。模型解释/生成只按一次请求传递必要输入，返回候选和校验
信息，由本地完成保存；不能借任务日志长期保留完整私有库。BYOK 凭据、托管请求的留存/删除和
迟到结果处理另设明确合同。普通同步也不授权把整个个人库自动提供给模型。

本地导出/备份保留对象身份、版本、必要材料/附件和校验清单；恢复先暂存校验再启用。
云端副本删除、账号解绑、退出、删除本地库分成不同意图。停止同步服务不删除本地内容或历史。

## 旧数据迁移与回退

1. 只读盘点旧 Account/Learner、材料、Run、Outcome、调度与未提交 outbox，记录数量/摘要/版本。
2. 确定源快照水位及待提交意图处理；开始切换后暂停旧链写入，保留完整源备份，禁止双写。
3. 导入隔离库，保留原 identity/provenance/时间。先核对引用和唯一性，再验证可继续的 Runtime。
   无法重放的旧版本以可审计导入记录保留，不伪造行为 Evidence 或新 Initial Handoff。
4. 验证记录数量、引用、材料 digest、目标/历史/下一次复习；通过后切换接收方。
5. 导入失败继续旧链；切换后若已有新本地事实，不能简单恢复旧快照丢掉它们，须导出增量或修复迁移。

隔离测试库不代表 owner 历史迁移验收；实际切换需要独立授权和可审阅的回退方案。


## Web 普通账号同步实现

`apps/web/src/data/library/cloudSync.ts` 复用既有本地事务及备份编码/校验。云端保存每个账号的
当前记录清单和按 SHA-256 寻址的数据块；图片和音频的既有内容表示随记录完整传输。
只传缺失的数据块，首次下载完整清单，后续复用本地和已确认基线的数据块以增量补齐。
当前媒体保存在这些数据库块中；独立对象存储分发仍属于资源上线工作，不宣称已完成 Storage 验收。

本地事务保存业务记录，已确认基线与当前记录的差异就是待同步变化；无需再次执行旧服务器学习命令。
发布前将不可变待传清单及幂等操作 ID 持久保存；云端以版本 CAS 原子替换清单，丢失回执后原样重试。
会话租约、账号凭据、设备密钥和 BYOK 配置不进入个人库同步；新浏览器保留自己的 deviceId。
后台生成中的材料在其他浏览器恢复为可重试状态，不继承原进程租约。

下载先完成引用验证与原学习运行时回放，随后在本地事务中再次检查账号、库 incarnation 及捕获版本。
同步期间继续产生的本地修改触发重试，不覆盖新数据。学习事件与领域操作历史在云端只能追加。
冲突采用三方记录比较；冲突与其引用关联的记录共同保留在各自版本中，独立记录仍可同步。
候选依赖图不能通过校验时暂停应用；账号页显示冲突/失败并提供重试，首发不自动选择学习历史胜方。
不同 identity 且已有本地内容的库不会自动合并；空浏览器可采用账号已有库身份后恢复。

`0029_sensa_library_sync.sql` 提供账号库、数据块及提交回执；仅后端受限角色可访问，接口逐条
限定认证账号，插件凭据不能调用此主应用同步接口。账号删除级联删除该账号库、块及回执。
每块请求大小、单次库大小和存储容量均有工程保护，不代表已确定收费套餐；旧未引用块暂保留供重试，
尚不进行自动回收。具体错误不伪装成已同步，云端同步也不提供历史快照备份承诺。

验证入口 `npm run sensa:library-cloud-smoke` 使用一次性本地 Postgres、真实浏览器和原始学习资源包，
不调用付费模型。需要 `SENSA_TEST_DATABASE_URL` 指向已迁移的 `127.0.0.1/sensa_m1a_*` 测试库，
以及已验证的 `release-candidate/assurance-catalog.json` 与对应包（可用既有无生成的打包脚本准备）。
可指定 `SENSA_CHROMIUM_PATH`；设置 `SENSA_LOCAL_WEB_URL` 后同时验证正式账号页，Auth HTTP 为合成服务。
此入口覆盖断网、回执丢失、同步期间本地写入、冲突中的独立变更、账号隔离、三元组/生成材料/学习/媒体恢复，
并验证 BYOK 密钥未上传、服务端拒绝历史改写和账号删除级联清理。
旧 `noteService` 的预览笔记仍在未绑定账号的 localStorage，本入口不会擅自迁移这些数据；账号笔记接线另行收敛。

## 待收敛的旧加密采集实现

`packages/intake-transport` 使用固定版本 jose 的标准 JWE：采集/设备授权采用 ECDH-ES（P-256）与
A256GCM；独立恢复码是设备随机生成的 256 位密钥，用 dir/A256GCM 包裹交付私钥。恢复码不上传，
插件只接收公钥与库/账户绑定，不接收解密私钥。受保护头和解密负载都检查账户、库、密钥及操作身份。
设备批准要求在新旧设备核对公钥指纹；授权信封只可由申请设备解开，请求有效期 10 分钟。
这不是自定义加密算法，也不把账号口令当作加密密钥。

账户设置的“设备与数据”提供启用/暂停、恢复码和设备批准。只有用户确认保存恢复码后才配置服务。
开启后新采集才附加加密信封，旧队列不自动上云。暂停保留本地内容及已交付密文；恢复继续交付。
同一信封持久化后原样重试，云端收件回执和本地入库回执分离。Web 解密后复用 `receiveWebIntake`，
不另写 Acceptance/Meaning 或学习入学。服务器收到入库回执后删除该密文，保留摘要和最小去重回执。

此交付收件箱不是历史备份或多设备内容广播。新设备目前先通过既有加密备份恢复同一个库，随后用
恢复码或原设备批准恢复交付密钥；不能凭恢复码恢复此前已交付并清除的内容/学习历史。交付私钥及
待批准设备私钥从学习库导出中排除，避免把设备授权通过备份隐式复制。完整库恢复/同步另行实现。

旧实现关联数据库迁移 `0028_sensa_encrypted_intake.sql`；不再按这条旧链直接推进生产发布。迁移只能
走 CI/CD；本地一次性 Postgres/浏览器测试不等于真实云端已启用。生产监控、账户容量策略和库密钥
轮换仍属于发布门，不以本模块的工程队列限制宣称免费套餐额度。
