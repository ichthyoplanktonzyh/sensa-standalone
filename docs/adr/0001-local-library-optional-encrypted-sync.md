# 完整本地学习库与可选加密同步

Owner 确认 Sensa 采用完整本地学习库、可选端到端加密同步、可下载学习资源与按需在线服务。
目的是让用户持续拥有资料和基本学习能力，同时保留便利的跨设备体验。
允许 Sensa 同步服务器保存密文副本，不再考虑禁止服务器保存任何形式副本的方案。
本决策确认目标方向；当前服务器权威实现尚未迁移，不代表现有同步已具备端到端加密。


2026-09-10 体验层修订：首次创建账号/登录是默认必要入口，Sensa 为默认在线服务，BYOK 为高级选项。
本 ADR 关于无在线依赖的条款约束已初始化本地库的执行与持续可用性，不再要求首次使用提供免账号旁路。
首次入口变化不转移学习事实权威，不取消离线继续、个人资料所有权或可选同步。
具体用户旅程以 [PRD](../sensa/product-requirements-v1.md) 为准。

## 已确认的边界

- 个人上下文、Expression、已确认的 Sense、个人材料、学习历史和调度状态属于用户的本地学习库。
  用户不购买同步、停止同步订阅或服务暂时不可用时，仍可使用已有本地资料完成基本学习。
- 同步是可选服务：数据在设备端加密、设备端解密，Sensa 不持有可解密个人同步内容的密钥。
  服务端允许保存密文副本及必要的服务元数据；不能宣称服务器完全不保存数据。
- 公共学习资源由 Sensa 发布，用户选择下载。公共资源版本更新与个人学习历史分开处理，
  不因重新下载覆盖既有学习事实；具体资源许可和分发机制另行确定。
- 在线解释、材料生成等能力单独提供。用户主动调用时可以传输必要输入；同步内容的端到端
  加密不等于在线模型调用不接触明文。路由、留存、日志与第三方处理边界需在服务设计中明确。
- 账号、订阅和服务用量与个人学习内容分开。在线服务认证不能成为读取本地库及基本学习的前置条件。
- 本地备份、历史恢复、导出与同步分别设计；跨设备一致不等于备份，也不保证误删除可以恢复。

## 架构后果

原来“Postgres 权威保存个人事实、客户端仅存意图与投影”的约束不再是目标架构。
现有 API/Postgres/outbox 流程保留为迁移前实现，不能靠切换存储位置就声称完成本地优先改造。

Meaning 接受、学习结果结算、Evidence/5D 投影及 FSRS 调度应由可在本地执行的领域逻辑处理。
UI 仍不能绕过校验直接填写派生状态；模型输出仍不是 Acceptance 或学习证据。
多设备并发时的事实身份、去重、合并和调度收敛必须明确，不能简单复制数据库文件或采用
“最后写入覆盖”抹掉一次学习。原有 Sense/Target 身份、协议版本、Outcome 与幂等不变量继续适用。

同步服务器负责密文同步的访问和传输，不能依赖读取个人明文来裁决语义或学习结果。
Postgres 仍可服务于账号、资源目录及在线服务，其具体职责和托管选型留待迁移设计。

## 下一步设计与验收

以下是决策落地前必须补齐的设计工作，不在本次直接实施：

1. 本地库身份、设备授权、账号绑定/解绑和浏览器采集到本地库的交接；核对 Web 与 Flutter 的交付顺序。
2. 本地领域执行边界、跨语言实现策略、不可变事实与同步冲突规则；复用已有合同、校验和回归资产。
3. 密钥创建、设备加入、密钥恢复/丢失、撤销与轮换，以及附件同步。撤销设备不能承诺收回其已经解密的副本。
4. 在线模型和材料服务的必要输入、用户自带 Provider 凭据、私有生成结果的返回与留存策略。
5. 旧账号/历史/待同步操作的迁移、备份与回退；同步账号删除、云端副本删除和本地库删除分别定义。

首批验收场景至少包括：无在线账号使用本地资料学习；断网重启后继续；两台离线设备分别学习后
不丢记录且调度可解释地收敛；停止同步订阅仍能本地学习；新设备恢复；误删恢复；旧数据迁移可回退。

此决策需要逐步修订架构、阶段、PRD 与消费合同中相关服务器权威条款。修订期间，上述目标方向
优先；原文保留的服务器专属规则用于理解现有实现，不可据此否定已经确认的本地库方向。
浏览器体验优化仍按原决定暂停，问题清单保留；本次不改运行代码、不迁移数据、不推送或部署。
