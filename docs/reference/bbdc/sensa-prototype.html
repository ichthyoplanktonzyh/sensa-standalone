五个 `.candidate.json` 均为 draft candidate package。它们只用于本原型，未宣称 published 或 production-qualified；手机界面不展示这层内部 provenance。

壳层与内核边界

  • Product Shell：沉浸首页、Learn / Review、词书 sheet、进度、计划/偏好、个人中心、全屏例句卡。
  • Learning Kernel：experience-first grounding、边界辨析、提取修复、减少脚手架重试、陌生语境完形。
  • 一次完成：每个 completed Encounter 只登记一条 Memory Outcome；被动阅读和 acknowledgement 不增加 Evidence。
  • 身份：手机按单词聚合列表，但当前学习、收藏和掌握声明都绑定具体 Sense；同一个单词的不同意思分别学习、分别记录进度。

已知契约缺口

  • 当前原型内的 Sense 收藏与例句收藏只在本页内存；生产需要 Sense bookmark、Example Learning Asset bookmark 的持久化与 Sensa Sync contract。
  • 撤回按钮不改写 append-only Attempt / Evidence；生产需要明确的 undo/navigation 生命周期契约。
  • abc 拼写入口与“看提示”只是显式的 UI 入口；冻结 V1 packet 没有 on-demand spelling/reveal Action，应新增版本化 Action contract 后才能写 Evidence。
  • 候选包的音频字节没有嵌入单文件；播放按钮会诚实提示 unavailable，不伪造播放成功。生产应接入 approved media blob。
  • 熟是 learner×Sense 的可逆声明，不是 Evidence、Memory Outcome 或 FSRS rating；生产需走声明/撤销接口并取消或阻断相关 Encounter。
  • 同一 Lexeme 的 sibling Sense 不应在无显式 boundary work 时连续排程；这是当前产品建议，未在本原型声称已由 Planner 实现。
  • 随身听的回顾/预习需要按 Sense 组织音频队列；当前冻结契约没有 Sense-aware audio queue contract。
  • 随堂测需要版本化的 dictation Action/session contract；当前原型只表达入口，不产生听写证据或结果。
  • 笔记需要离线保存、同步和归属到具体意思的 persistence contract；当前原型只保留空入口。
